# TrueNAS SCALE: зеркальный пул данных на тех же SSD, что и boot-pool

> ⚠️ **Неофициальная схема.** Разбиение загрузочных дисков TrueNAS под данные
> не поддерживается разработчиками. Действуйте на свой риск. Перед любыми
> изменениями сделайте резервную копию конфига TrueNAS и убедитесь, что у вас
> есть физический доступ к серверу.

---

## 📖 Что это

Пошаговая инструкция (и вспомогательный скрипт `setup_dataset.py`) для
сценария, когда нужно:

- Держать **`boot-pool`** (система TrueNAS) на двух SSD в зеркале.
- Использовать **оставшееся место** на этих же SSD под зеркальный
  **`data_pool`**.
- Уметь заменить вышедший из строя SSD, не потеряв оба пула.

Схема работает **только если на дисках есть неразмеченное свободное место
в конце**. По умолчанию установщик TrueNAS SCALE занимает **весь диск**
под `boot-pool`, поэтому место нужно закладывать **на этапе установки**.

---

## ⚙️ Требования

- TrueNAS SCALE (тестировалось на Community Edition, 25.x).
- Два одинаковых SSD (в примерах — `/dev/sda`, `/dev/sdb`).
- Доступ к консоли / SSH с правами `root`.
- Установочная флешка TrueNAS (для переустановки или ремонта загрузки).
- Утилиты: `sgdisk`, `partprobe`, `zpool`, `blkid`, `partx`, `fdisk`.
  В TrueNAS SCALE уже есть.

---

## 🧭 Схема разделов (целевая)

На каждом SSD:

| Раздел | Размер     | Тип (GUID)   | Назначение              |
|--------|------------|--------------|-------------------------|
| `sdX1` | 1 МБ       | BIOS boot    | Загрузчик (BIOS)        |
| `sdX2` | 512 МБ     | EFI System   | Загрузчик (UEFI)        |
| `sdX3` | 32 ГБ      | BF01 (ZFS)   | `boot-pool`             |
| `sdX4` | остаток    | BF01 (ZFS)   | `data_pool` (зеркало)   |

> 💡 Размер `sdX3` (32 ГБ) — пример. Можно сделать 16, 64 или другой разумный.

---

## 🛠️ Пути реализации

### Путь A. Ручная разметка при установке TrueNAS (рекомендуется)

1. Загрузиться с установочной флешки TrueNAS.
2. В меню установщика выбрать **Shell**.
3. Отредактировать скрипт установки, чтобы `boot-pool` создавался на 32 ГБ,
   а не на всём диске:
   ```bash
   vi /usr/sbin/truenas-install
   ```
   Найти строку, где создаётся 3-й раздел (обычно `sgdisk -n3:0:0` или
   `sgdisk -n3:0:+32GiB`), и убедиться, что указан ограниченный размер,
   например:
   ```
   sgdisk -n3:0:+32GiB -t3:BF01 /dev/sda
   sgdisk -n3:0:+32GiB -t3:BF01 /dev/sdb
   ```
4. Запустить установку. TrueNAS создаст `boot-pool` на `sdX3`, оставив
   остаток диска свободным.
5. После первой загрузки в TrueNAS — создать `data_pool` из 4-х разделов
   (см. раздел «Создание data_pool»).

### Путь B. Переразметка без переустановки (рискованно)

> ⚠️ Потребуется экспорт `boot-pool`. Если что-то пойдёт не так —
> система не загрузится, придётся ремонтировать через установочную флешку.

1. `zpool export boot-pool`
2. Удалить и пересоздать раздел `sdX3` меньшего размера.
3. Создать `sdX4` из остатка.
4. `zpool import boot-pool`
5. Проверить, что EFI-раздел (`sdX2`) ссылается на новый `sdX3`.

Если не уверены — **не идите этим путём**.

### Путь C. Данные на отдельных дисках (штатно)

Самый безопасный и «правильный» для TrueNAS способ: оставить SSD
только под `boot-pool`, а `data_pool` собрать из других дисков
(HDD или отдельных SSD).

## 🧱 Создание data_pool

### 1. Проверка дисков

```bash
fdisk -l
```

Убедиться, что на `sdX` есть **неразмеченное место в конце** (иначе
дальше идти нет смысла — вернитесь к Пути A).

### 2. Создание 4-го ZFS-раздела

```bash
sgdisk -n4:0:0 -t4:BF01 /dev/sda
sgdisk -n4:0:0 -t4:BF01 /dev/sdb
partprobe
```

| Флаг       | Значение                                    |
|------------|---------------------------------------------|
| `-n4:0:0`  | Создать раздел №4 от начала свободного места до конца диска |
| `-t4:BF01` | Тип раздела BF01 — код ZFS в GPT            |
| `partprobe`| Заставить ядро перечитать таблицу разделов  |

### 3. Создание зеркала

Вариант А — по именам устройств:

```bash
zpool create data_pool mirror /dev/sda4 /dev/sdb4
```

Вариант Б — по PARTUUID (рекомендуется):

```bash
blkid /dev/sda4
blkid /dev/sdb4

zpool create -f data_pool mirror \
  /dev/disk/by-partuuid/<UUID_sda4> \
  /dev/disk/by-partuuid/<UUID_sdb4>
```

> ⚠️ В оригинальной инструкции встречается опечатка: `data_pool` и
> `datapool`. Используйте **одно** имя.

### 4. Экспорт для импорта в веб-интерфейсе

```bash
zpool export data_pool
```

Затем в TrueNAS: **Storage → Import Pool → data_pool**.

## 🔄 Замена SSD

### 1. Восстановление видимости разделов

```bash
sudo partx -v -s /dev/sde
sudo partx -v -s /dev/sdf
```

### 2. Отключить и удалить старый раздел от boot-pool

```bash
zpool detach boot-pool sde3
sgdisk -d 3 /dev/sde
```

### 3. Создать новые разделы на новом SSD

```bash
sgdisk -n 3:0:+32GiB -t3:BF01 /dev/sde
sgdisk -n4:0:0      -t4:BF01 /dev/sde
```

### 4. Подключить новый раздел к boot-pool

```bash
zpool attach boot-pool /dev/sdf3 /dev/sde3
```

`sdf3` — существующий рабочий раздел загрузочного пула, к которому
«прицепляется» зеркало.

### 5. Проверка и замена в зеркале данных

```bash
zpool status data_pool
sudo partx -v -s /dev/sde

zpool replace <имя_пула> <имя_недоступного_диска> \
  /dev/disk/by-partuuid/<UUID_четвёртого_раздела_нового_SSD>
```

## 🐍 Скрипт setup_dataset.py

Скрипт автоматизирует шаги выше в **интерактивном режиме** — спрашивает
подтверждение на каждом шаге, поддерживает `--dry-run` и выполнение
отдельного шага.

### Использование

```bash
# Полный интерактивный прогон
sudo python3 setup_dataset.py --disks /dev/sda /dev/sdb

# Только показать команды
sudo python3 setup_dataset.py --dry-run

# Использовать PARTUUID при создании пула
sudo python3 setup_dataset.py --use-partuuid

# Выполнить только шаг 3 (создание пула)
sudo python3 setup_dataset.py --step 3 --use-partuuid

# Сменить имя пула
sudo python3 setup_dataset.py --pool mydata
```

### Ключи

| Ключ                | Описание                                              |
|---------------------|-------------------------------------------------------|
| `--disks`           | Диски для зеркала (по умолчанию `/dev/sda /dev/sdb`)  |
| `--pool`            | Имя пула данных (по умолчанию `data_pool`)            |
| `--boot-pool`       | Имя загрузочного пула (по умолчанию `boot-pool`)      |
| `--boot-size`       | Размер boot-раздела (по умолчанию `32GiB`)            |
| `--use-partuuid`    | Использовать PARTUUID вместо `/dev/sdX`               |
| `--dry-run`         | Показать команды без выполнения                       |
| `--yes-to-all`      | ⚠️ Автоматически отвечать `y` на все подтверждения    |
| `--step N`          | Выполнить только шаг N (1–8). `0` = все шаги.         |

### Шаги скрипта

1. Просмотр дисков (`fdisk -l`).
2. Создание 4-го ZFS-раздела (`sgdisk -n4:0:0 -t4:BF01`).
3. Создание зеркального пула (`zpool create ... mirror`).
4. Экспорт пула для импорта через веб-интерфейс.
5. `partx -v -s` для восстановления видимости разделов.
6. Замена загрузочного диска (`detach` / `sgdisk` / `attach`).
7. Проверка статуса пула и разделов.
8. `zpool replace` для замены недоступного диска в зеркале.

## ⚠️ Риски и предупреждения

1. **Неофициальная схема.** Обновления TrueNAS могут сломать разметку.
2. **Опечатки в оригинальной инструкции.** `data_pool` и `datapool` —
   разные имена. Используйте одно.
3. **`/dev/sdX` ненадёжен.** Буквы дисков могут меняться. Предпочитайте
   `by-partuuid`.
4. **`zpool create` без `-f`** откажется работать, если на разделе
   обнаружена чужая ФС. `-f` уничтожит данные на этих разделах.
5. **`boot-pool` — критичный пул.** Ошибка при его переносе = нерабочая
   загрузка. Держите под рукой установочную флешку.
6. **Бэкап обязателен.** И конфига TrueNAS (`System → General → Save Config`),
   и данных.

---

## ✅ Что получится в итоге

- `boot-pool` — зеркало из двух разделов по 32 ГБ (по одному на SSD).
- `data_pool` — зеркало из двух 4-х разделов, занимающих остаток места.
- Оба пула используют **одни и те же физические диски**, но разные разделы.
- При выходе из строя одного SSD система продолжает работать, а диск можно
  заменить по шагам выше.

## 📚 Полезные команды

```bash
# Статус пулов
zpool status
zpool status boot-pool
zpool status data_pool

# Список дисков и разделов
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT
fdisk -l

# PARTUUID разделов
blkid /dev/sda4 /dev/sdb4

# Импорт/экспорт пула
zpool export data_pool
zpool import data_pool
```

---

## 📝 Заметки

- Имя `data_pool` — пример. Можно `tank`, `storage`, `nas` и т.п.
- Размер `boot-pool` (32 ГБ) взят с запасом. TrueNAS сам требует
  минимум ~16 ГБ, но 32 ГБ удобнее для обновлений и снапшотов.
- Схема проверялась на SSD Kingston A400 (111.79 GiB). На дисках
  другого объёма логика та же, меняются только цифры.
